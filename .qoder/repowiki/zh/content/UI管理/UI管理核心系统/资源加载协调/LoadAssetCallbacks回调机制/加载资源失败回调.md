## 委托设计与参数解析

加载资源失败回调（LoadAssetFailureCallback）是游戏框架中用于处理资源加载失败的核心委托。该委托定义在 `LoadAssetFailureCallback.cs` 文件中，其签名如下：

```csharp
public delegate void LoadAssetFailureCallback(string assetName, LoadResourceStatus status, string errorMessage, object userData);
```

该委托包含四个参数，分别用于传递加载失败的关键信息：

- **assetName**: 表示尝试加载的资源名称，用于定位具体失败的资源。
- **status**: 表示加载资源的状态，具体为 `LoadResourceStatus` 枚举类型，用于分类错误类型。
- **errorMessage**: 提供详细的错误信息，帮助开发者诊断问题。
- **userData**: 用户自定义数据，用于在回调中恢复上下文和传递业务逻辑所需的信息。

## LoadResourceStatus 枚举详解

`LoadResourceStatus` 枚举定义了资源加载过程中可能出现的各种状态，位于 `LoadResourceStatus.cs` 文件中。该枚举通过不同的值来分类加载失败的原因，便于上层逻辑进行针对性处理。

```csharp
public enum LoadResourceStatus : byte
{
    Success = 0,
    NotExist,
    NotReady,
    DependencyError,
    TypeError,
    AssetError
}
```

各状态的含义如下：

- **Success**: 资源加载成功。
- **NotExist**: 请求的资源不存在，可能是路径错误或资源未打包。
- **NotReady**: 资源尚未准备完毕，可能由于依赖资源未加载完成。
- **DependencyError**: 依赖资源加载失败，导致当前资源无法加载。
- **TypeError**: 资源类型错误，例如尝试将非预制体资源作为预制体加载。
- **AssetError**: 加载资源时发生错误，可能是文件损坏或读取异常。

这些状态为框架提供了细粒度的错误分类，使得上层逻辑可以根据不同的错误类型采取相应的恢复策略。

```csharp
private void LoadAssetFailureCallback(string uiFormAssetName, LoadResourceStatus status, string errorMessage, object userData)
{
    OpenUIFormInfo openUIFormInfo = (OpenUIFormInfo)userData;
    // ...
}
```

如果 `openUIFormInfo` 为 null，则抛出异常。接着，检查 `m_UIFormsToReleaseOnLoad` 集合，如果存在对应的序列 ID，则从集合中移除并返回，表示该界面已被取消加载。

## 上下文恢复与队列清理

在三大系统的实现中，`userData` 参数起到了关键作用。它携带了加载资源时的上下文信息，如 `OpenUIFormInfo`、`ShowEntityInfo` 和 `PlaySoundInfo`。这些信息在加载失败时用于恢复上下文，确保系统状态的一致性。

此外，每个系统都维护了一个待加载队列（如 `m_UIFormsBeingLoaded`、`m_EntitiesBeingLoaded`、`m_SoundsBeingLoaded`）和一个待释放队列（如 `m_UIFormsToReleaseOnLoad`、`m_EntitiesToReleaseOnLoad`、`m_SoundsToReleaseOnLoad`）。当加载失败时，系统会从待加载队列中移除对应的条目，并根据情况清理待释放队列，防止资源泄漏。

## 失败事件触发机制

当资源加载失败且未被取消时，系统会触发相应的失败事件。例如，在 UI 系统中，会触发 `OpenUIFormFailure` 事件，并传递 `OpenUIFormFailureEventArgs` 对象。

```csharp
if (m_OpenUIFormFailureEventHandler != null)
{
    OpenUIFormFailureEventArgs openUIFormFailureEventArgs = OpenUIFormFailureEventArgs.Create(openUIFormInfo.SerialId, uiFormAssetName, openUIFormInfo.UIGroup.Name, openUIFormInfo.PauseCoveredUIForm, appendErrorMessage, openUIFormInfo.UserData);
    m_OpenUIFormFailureEventHandler(this, openUIFormFailureEventArgs);
    ReferencePool.Release(openUIFormFailureEventArgs);
    return;
}
```

类似的机制也应用于实体和声音系统，分别触发 `ShowEntityFailure` 和 `PlaySoundFailure` 事件。这些事件允许上层逻辑进行自定义的错误处理，如显示错误提示或记录日志。

## 错误处理模式

框架在处理加载失败时采用了两种模式：

1. **事件通知模式**: 通过触发事件通知上层逻辑，允许上层代码进行自定义处理。这种模式适用于需要用户反馈或复杂恢复逻辑的场景。
2. **异常终止模式**: 如果没有注册事件处理器，则抛出 `GameFrameworkException` 异常，终止当前流程。这种模式适用于必须确保资源加载成功的场景。

这两种模式的结合使得框架既灵活又健壮，能够适应不同的应用场景。

## 错误传播与用户反馈

通过事件通知模式，框架将错误信息传播到上层逻辑，使得开发者可以根据具体的错误类型和上下文提供用户反馈。例如，当资源不存在时，可以提示用户检查资源路径；当依赖资源错误时，可以提示用户检查依赖关系。

异常终止模式则确保了在关键资源加载失败时，系统不会进入不一致的状态。这种设计平衡了用户体验和系统稳定性，使得框架在面对各种错误情况时都能做出合理的响应。
