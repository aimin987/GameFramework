## 委托定义与参数说明

`LoadAssetSuccessCallback` 是一个委托类型，定义在 `GameFramework.Resource` 命名空间下，用于在资源加载成功后触发的回调函数。该委托在资源系统中被广泛使用，作为资源加载完成后的统一处理入口。

其定义如下：
```csharp
public delegate void LoadAssetSuccessCallback(string assetName, object asset, float duration, object userData);
```

各参数含义如下：

- **assetName**：表示成功加载的资源名称，通常为资源路径或标识符，用于定位和识别资源。
- **asset**：表示已加载的资源对象本身，通常为 Unity 中的 `Object` 或其派生类型，如 `GameObject`、`AudioClip` 等。
- **duration**：表示资源加载所花费的时间（以秒为单位），可用于性能监控或加载进度展示。
- **userData**：用户自定义数据，用于在异步加载过程中传递上下文信息，在回调中可进行类型转换并恢复业务逻辑所需的状态。

该委托在 `LoadAssetCallbacks` 类中被封装为属性，供资源管理器调用。

## UIManager中的实现与流程

在 `UIManager` 中，`LoadAssetSuccessCallback` 被用于处理 UI 界面资源加载成功后的逻辑。当调用 `OpenUIForm` 方法时，若资源尚未缓存，则通过 `ResourceManager` 异步加载资源，并将 `OpenUIFormInfo` 作为 `userData` 传入。

回调函数 `LoadAssetSuccessCallback` 的执行流程如下：

1. **类型转换与验证**：将 `userData` 转换为 `OpenUIFormInfo` 类型，验证其有效性。
2. **加载取消检测**：检查该 UI 是否已被标记为“释放加载中”，若是，则释放资源并返回。
3. **状态清理**：从 `m_UIFormsBeingLoaded` 字典中移除该 UI 的加载记录。
4. **实例化与注册**：通过 `UIFormHelper` 实例化 UI 对象，创建 `UIFormInstanceObject` 并注册到对象池。
5. **内部打开流程**：调用 `InternalOpenUIForm` 方法，完成 UI 的初始化、打开、事件触发等操作。
6. **资源回收**：释放 `OpenUIFormInfo` 对象，避免内存泄漏。

此流程确保了 UI 界面在资源加载完成后能够正确实例化、初始化并显示，同时维护了加载状态和对象池管理。

## EntityManager中的实现与流程

在 `EntityManager` 中，`LoadAssetSuccessCallback` 用于处理实体资源加载成功后的逻辑。当调用 `ShowEntity` 方法时，若实体资源未缓存，则启动异步加载，并将 `ShowEntityInfo` 作为 `userData` 传入。

回调函数的执行流程如下：

1. **类型转换与验证**：将 `userData` 转换为 `ShowEntityInfo`，确保其不为空。
2. **加载取消检测**：检查该实体是否已被标记为“释放加载中”，若是，则释放资源并返回。
3. **状态清理**：从 `m_EntitiesBeingLoaded` 字典中移除该实体的加载记录。
4. **实例化与注册**：通过 `EntityHelper` 实例化实体对象，创建 `EntityInstanceObject` 并注册到所属实体组的对象池中。
5. **内部显示流程**：调用 `InternalShowEntity` 方法，完成实体的创建、初始化、添加到实体组、触发 `OnShow` 回调等操作。
6. **资源回收**：释放 `ShowEntityInfo` 对象。

该流程实现了实体的异步加载与动态创建，确保了实体在加载完成后能够正确加入场景并进入运行状态。

## SoundManager中的实现与流程

在 `SoundManager` 中，`LoadAssetSuccessCallback` 用于处理声音资源加载成功后的播放逻辑。当调用 `PlaySound` 方法时，若声音资源未缓存，则启动加载，并将 `PlaySoundInfo` 作为 `userData` 传入。

回调函数的执行流程如下：

1. **类型转换与验证**：将 `userData` 转换为 `PlaySoundInfo`，确保其有效性。
2. **加载取消检测**：检查该声音是否已被标记为“释放加载中”，若是，则释放资源并返回。
3. **状态清理**：从 `m_SoundsBeingLoaded` 列表中移除该声音的加载记录。
4. **播放声音**：调用 `SoundGroup.PlaySound` 方法，将加载的 `soundAsset` 传递给声音代理进行播放。
5. **事件触发**：若播放成功，触发 `PlaySoundSuccess` 事件；若失败，则触发 `PlaySoundFailure` 事件。
6. **资源回收**：释放 `PlaySoundInfo` 及其关联的 `PlaySoundParams`（若标记为引用）。

该流程确保了声音资源在加载完成后能够立即播放，并通过事件机制通知上层逻辑，同时处理了播放失败的异常情况。

## userData上下文传递机制

`userData` 参数是 `LoadAssetSuccessCallback` 实现业务解耦的关键。它允许在发起资源加载请求时，将当前上下文信息（如 UI 打开参数、实体显示信息、声音播放参数）封装并传递到异步回调中。

具体实现方式如下：

- **UI 系统**：使用 `OpenUIFormInfo` 封装 `SerialId`、`UIGroup`、`PauseCoveredUIForm` 和 `UserData`，在回调中恢复 UI 打开所需的全部信息。
- **实体系统**：使用 `ShowEntityInfo` 封装 `SerialId`、`EntityId`、`EntityGroup` 和 `UserData`，用于恢复实体显示的上下文。
- **声音系统**：使用 `PlaySoundInfo` 封装 `SerialId`、`SoundGroup`、`PlaySoundParams` 和 `UserData`，确保声音能正确播放并触发事件。

这些信息类均实现 `IReference` 接口，通过对象池（`ReferencePool`）进行复用，避免频繁的 GC 分配，提升性能。

## 资源释放与状态更新

`LoadAssetSuccessCallback` 在资源加载成功后，承担了关键的资源管理和状态更新职责：

1. **状态清理**：从“正在加载”集合（如 `m_UIFormsBeingLoaded`、`m_EntitiesBeingLoaded`）中移除记录，更新系统状态。
2. **资源释放**：对于被取消的加载请求，立即释放已加载的资源（通过 `ReleaseUIForm`、`ReleaseEntity`、`ReleaseSoundAsset`），防止内存泄漏。
3. **事件触发**：在 UI、实体、声音系统中，分别触发 `OpenUIFormSuccess`、`ShowEntitySuccess`、`PlaySoundSuccess` 事件，通知上层逻辑加载完成。
4. **后续流程推进**：调用 `InternalOpenUIForm`、`InternalShowEntity` 等内部方法，推进业务流程进入下一阶段。

该机制确保了资源加载的原子性、状态的一致性以及业务流程的连贯性，是框架异步资源管理的核心组成部分。
